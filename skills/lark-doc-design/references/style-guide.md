# 飞书文档样式规范 v0.3

- 状态：草案。2026-10-20～21 在一套 9 篇的团队 Git 协作手册上验证过，用户已确认。
- 适用：团队内部的规范、操作说明、规则查询类飞书文档。对外文档、汇报材料和幻灯片不适用。
- 标了“待验证”的条目，确认之前不要依赖。
- 变更记录见 [../CHANGELOG.md](../CHANGELOG.md)。

## 0. 核心原则：先想清楚要表达什么，再选形式

文字只是表达方式之一。写每一段之前，先回答两个问题：

1. **这段要让读者做到什么？** 知道一件事、照着操作、在几种情况里选一个、找到某个人，还是查到一个值。
2. **只看文字，读者会卡在哪？** 找不到按钮、理不清先后顺序、分不清两个概念，还是在一大段话里找不到自己的情况。

然后选最能解决这个卡点的形式。读者靠文字就能看懂的，就用文字。组件只是工具，不是越多越好。

改写已有文档或者写新文档，都按节来做：

1. **把这一节要讲的事列出来，不改动内容。** 规则一条都不能丢，也不要趁机改规则。
2. **每一节回答上面两个问题**，“读者要做到什么”和“卡在哪”各写一句话。
3. **按第 1 节的对照表选形式。** 一节可以组合好几种，但每种都要能说出它解决了哪个卡点。
4. **核对信息有没有丢。** 换成图或表之后，原文的每一条在新版里都要能找到。图里放不下的，补在图下面的文字里。

例子见 [examples.md](examples.md)。

## 1. 读者要做到什么 → 用什么形式

| 读者要… | 只用文字的问题 | 用什么（飞书里的名字） |
|---|---|---|
| 知道点哪里、点完是什么样 | 用文字描述界面很吃力 | **图片**（带标注的截图，见第 2 节）；连续好几步的操作，用动图或短视频（**视频或文件**） |
| 理解先后顺序 | “先……再……然后……”，读到后面就忘了前面 | **流程图**、**画板** |
| 在几种情况里选一个 | “如果……就……否则……”层层嵌套 | 带分支判断的**流程图** |
| 分清两个容易混的东西 | 来回解释，越说越乱 | **分栏**对照，或者在**画板**里把两边画出来 |
| 比较几个对象的同一组属性 | 一个对象写一段，没法横着比 | **表格** |
| 看清整体结构 | 列表一层套一层 | **思维导图** |
| 找到人、找到群 | 只写一个名字，读者还得自己去搜 | **人员**（@人，见第 7 节）、**群名片** |
| 跟踪事项的进度 | 用文字写的待办没人更新 | **任务清单**，或者直接链接到飞书项目 |
| 收集反馈 | 只写“有问题请反馈”，没有入口 | **信息收集**、**投票** |
| 在长文里跳到某一节 | 手写的目录容易过时 | **目录导航** |
| 照着复制 | 内容混在句子里，不好选中 | **代码块** |
| 多个页面讲同一段内容 | 复制成多份，改的时候漏掉几份 | **同步块** |
| 打开一个最主要的链接 | 链接埋在句子里，不显眼 | **按钮** |

规则：

- **图不能是唯一的信息来源。** 每张图、每个画板旁边，都要有一句文字说明它在讲什么。图片加载失败时、读者搜索时，靠的都是这句话。
- **一个形式解决一个卡点。** 说不出这个组件帮读者解决了什么，就不要用。
- **图和文字用同一套编号。** 图里标了 ①②③，下面的表格或步骤也用 ①②③，读者才能对上号。带 ①②③ 的步骤写成段落，不放进有序列表，否则飞书会再加一层“1. 2. 3.”，编号就重复了。
- **要来回对照的两张表，合成一张。** 例如职责表和权限表，合成一张多一列的表。
- **给不同的人看的内容，用分栏分开。** 每个人只看自己那一栏。
- **不用日期提醒和倒计时。** 日期直接写成文字。

## 2. 截图和画板

### 截图

截图是操作类文档里最重要的表达手段，要像对待正文一样认真处理。

| 要求 | 做法 |
|---|---|
| 只截相关区域 | 不截全屏，能看出“这是哪个窗口、哪一块”就够了 |
| 标出要点 | 用矩形框圈出要点的位置；一张图里有好几步，就在图上标 ①②③，正文的步骤用同样的编号 |
| 箭头少用 | 只在“从这里拖到那里”这种有移动的操作时用 |
| 一张图顶多张 | 同一个窗口里连着 3 步以上，用一张标了 ①②③ 的图，不要截 3 张 |
| 尺寸统一 | 同一页的截图宽度一致；要对照的两张图，用分栏并排放 |
| 图注说“看什么” | 写“检出后，左上角显示当前分支”，不要把步骤原样再抄一遍 |
| 遮掉敏感信息 | 账号、密码、Token、个人信息，先打码再截 |
| 还没截到 | 放灰底占位图，写“［待截图］”和要截的内容，不要空着 |

截图里统一用**红框**表示“看这里、点这里”，这是截图工具的默认颜色。正文里的红字只表示“禁止”，两者出现在不同地方，不会混淆。

### 画板（流程图、判断图、方向图）

| 要求 | 做法 |
|---|---|
| 框里的字要短 | 判断框尽量不超过 8 个字，例如“修 Bug？”。补充说明写在图下面的文字里 |
| 长框手动换行 | 名称和格式分两行写，例如名称一行，下一行写 `fixes/…` |
| 两个框之间不画来回两条线 | 两条线的标签会叠在一起。在中间加一个框把它拆开，例如在两个分支之间加一个“MR” |
| 线上的标签要短 | 线上只写编号和动作，例如“② merge”；谁来做、注意事项放到表格里 |
| 颜色有含义 | 读者最后要选的结果用蓝色；不合入、次要、交给别人做的用灰色；判断框用默认的橙色 |
| 画完要导出来看 | 导出缩略图，检查有没有文字被截断、标签重叠；有问题就改，改完重新导出 |

## 3. 结构

写之前先定三件事：

1. 这篇给谁看？
2. 读者什么时候打开它？按下表选类型、套骨架。
3. 这个话题别处写过吗？写过就只写一句话加链接，一个话题只在一处写全。

| 类型 | 读者打开它时 | 骨架 | 篇幅 |
|---|---|---|---|
| 入口 | 我该看哪篇 | 一句话说明 → 按角色导航 → 常用地址 → 找谁 | 1 屏 |
| 教程 | 第一次学，跟着做一遍 | 目标 → 前置 → 第 N 步（每步写清做完是什么样） → 做完的标志 | 2～3 屏 |
| 操作 | 做事时照着做 | 第一屏提示 → 流程图 → 第 N 步 → 常见情况 → 哪些事不归你 | 1～2 屏 |
| 排障 | 出问题了来查 | 按症状分组的表：看到什么 / 先做什么 / 别做什么 | 不限 |
| 参考 | 查一条规则 | 按读者会问的问题分节，每节单独能读懂；加目录导航 | 不限 |
| 解释 | 想弄懂为什么 | 图 → 文字说明 → 和以前比变了什么 | 2～3 屏 |
| 变更 | 规则改了什么 | 变更表 + 反馈入口 | 不限 |

**第一屏**：
- 蓝色 💡 高亮块，写一两句“这页帮你做什么”。
- 下面一段：开始前要准备什么、不会的找谁。
- 操作页再放流程图，图下面跟一句文字说明。
- 第一屏不放修订记录、维护人和长背景。

**页尾**：
- 不写“最后更新、维护人”。飞书页面顶部本来就显示最近修改时间，手写的日期很快会过时。
- 修订记录集中记在一页（例如试行页或变更页），各篇正文里不放。
- 正文最后一段写读者的下一步，例如求助按钮、回到入口。

## 4. 标题和行文

- 正文从**二级标题**开始，不用一级标题。
- 操作页、教程页只用一层：每个步骤或场景各占一个二级标题。参考页最多两层，开自动编号。
- 步骤标题写成“第 N 步　动作”，中间用全角空格。
- 标题里不放 emoji，不加粗，不上色。
- **一行只写一件事。** 补充说明换行另起。一行尽量不超过 30 字。
- 能用列表就不写长段落。列表项写成动作，例如“保存，关掉 Unity”。

## 5. 留白

用 `scripts/spacing.py` 自动加，不要手工加。

| 位置 | 放什么 |
|---|---|
| 每个二级标题前（包括第一个） | 一个空行，再加一条分割线 |
| 列表和紧跟的图片或分栏之间 | 一个空行 |
| 图片或分栏后面 | 一个空行 |
| 高亮块前后 | 各一个空行；页面开头的第一个块前面不加 |
| 按钮前 | 一个空行 |

除此之外不加空行，也不连续空两行。

## 6. 文字样式和块组件

| 样式 | 只用来表示 |
|---|---|
| 加粗 | 界面上的按钮名、菜单名；第一屏提示里最关键的一句；分栏开头的小标题 |
| 绿色字 | 做对了、成功了的结果（“✅ 完成后：”“✅ 成功了：”）；让人放心的栏目名，例如“交给程序” |
| 红色字 | 禁止事项的栏目名，例如“千万别做”；排障表的“别做什么”列 |
| 行内代码 | 分支名、路径、文件名、命令、版本号格式 |
| 中文引号“” | 示例文字、引用某种说法 |
| 斜体、其他颜色、背景色 | 不用 |

| 组件 | 只用来表示 | 规则 |
|---|---|---|
| 💡 蓝色高亮块 | 第一屏的“这页帮你做什么” | 每页 1 个 |
| ❗ 黄色高亮块 | 容易出错的地方 | 紧跟在对应步骤后面，每页最多 3 个；不要用 ⚠️，飞书会把它换成 💡 |
| ⛔ 红色高亮块 | 单独一条不可逆、会丢数据的警告 | 禁止事项有好几条时，改用分栏或列表放进一个 ⛔ 块里 |
| 引用块 | 跳过也不影响操作的补充说明 | 一两行 |
| 表格 | 多个对象的同一组属性；排障表 | 不超过 4 列；表头用浅灰；不拿表格排版 |
| 分栏 | 两组等量、要对照着看的内容；给不同的人看的内容 | 每栏开头放一个加粗的小标题，表示放心或禁止时用绿色或红色；每栏内容要短；手机上的显示效果待验证 |
| 勾选框 | 大家共用的检查清单 | 不要拿来做个人自检：所有人看到的是同一个勾选状态 |

## 7. 人和链接

- **人：** 用 @人，名字会关联到组织架构里的人员。用工具写入的 @ 实测不会通知对方（2026-10-21 测过）；在飞书界面里手动 @ 会不会通知，没有测过。同名的人，先核对部门再选。
- **其他飞书文档：** 用 @文档，它会显示目标文档的标题。目标文档改名后，这里的标题会不会跟着变，待验证。
- **外部网址：** 用普通链接，链接文字写清楚点了会去哪里。

## 8. 语气

- 操作页、排障页用第二人称和短句，可以用问句开头。参考页用中性语气。
- 不用“！！！”和“非常重要”。真正危险的地方，用红色或高亮块标出来。
- 发布前用 humanizer-zh 过一遍。

## 9. 发布前自查

其中带 [lint] 的项由 `scripts/lint.py` 自动检查，其余靠人工判断。

- 每一段都能说出“要让读者做到什么”；文字读着费劲的地方，已经换成了更合适的形式
- 每张图、每个画板旁边都有一句文字说明；图里放不下的信息，补在了文字里 [lint 只查有没有说明文字]
- 图和表格（或步骤）用的是同一套编号；带 ①②③ 的步骤没有放进有序列表 [lint]
- 画板导出看过，没有文字截断、标签重叠
- 改写已有内容时，原文的每一条规则都还在
- 截图只截了相关区域、标好了要点、遮掉了敏感信息
- 第一屏有 💡 提示；正文从二级标题开始，每个二级标题前都有空行和分割线 [lint]
- 没有超过 30 字还不换行的长句 [lint]
- 高亮块：蓝色 1 个，黄色最多 3 个，没有用 ⚠️ [lint]
- 同一个话题没有在别的页面再写全一遍
- 页尾没有手写的日期和维护人；最后一段是读者的下一步 [lint 只查页尾]
- 改已有文档时，没有动标题
